# Data-Subject Request Procedure

**School:** ______________________  **Owner:** ______________________
**Intake contact:** ______________________  **Response target:** per NDPA 2023 and school policy

Use this for access, correction, erasure, restriction, or objection requests from a student,
parent/guardian, or staff member. Verify identity and authority before disclosing or changing data.

## 1. Intake and verification

- [ ] Record the request date, requester, relationship to the student, and contact method.
- [ ] Verify identity and, for a child, parent/guardian authority or student capacity under school
      policy.
- [ ] Clarify the scope and format requested.
- [ ] Open a request log entry; do not put unnecessary personal data in email/chat.

## 2. Access / export

1. Hub admin signs in and opens **Students**.
2. Find the student and choose **Export**.
3. The JSON file includes student details, scores, comments, flags, and reports.
4. Review the file for third-party data or internal notes that must be redacted under school policy.
5. Hand over through the approved secure method and obtain an acknowledgement.
6. Delete the export file after closure unless retention requires it.

**Never** send the export by personal email, WhatsApp, or an unapproved cloud link.

## 3. Correction

- Name/class: **Students → Edit**. Record the source of the corrected value.
- Score: **Scores → Correct or remove a score**, with an 8+ character reason. A correction appends an
  immutable version; do not delete/re-enter to hide the change.
- Comment/report: follow the school's report correction/version process; locked reports are not
  silently overwritten.
- Tell the requester what changed and, if relevant, who approved it.

## 4. Erasure

1. Confirm there is no legal/retention obligation to keep the record; record the decision.
2. **Students → Delete**, typing the student code. This removes live scores, comments, flags, and
   reports; the audit log remains.
3. Decide whether backups must be pruned under the retention schedule. Backups are not deleted by the
   student delete action.
4. If a full offboarding wipe is required, use **Backup → Purge all live data** (`PURGE`), then delete
   the data folder and backups not under legal hold.
5. Record what was deleted, from which locations, by whom, and the approver.
6. Do not tell the requester that every copy is gone unless primary, secondary, and off-site copies
   have been handled.

## 5. Response

- [ ] Provide the response in plain language.
- [ ] Explain any lawful exception or retention obligation.
- [ ] Give the school/DPO contact and the right to complain to the NDPC.
- [ ] Close the log entry with date, decision, and evidence location.
