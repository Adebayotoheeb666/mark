Plain language

Privacy and the pilot gate

Short version: the desktop app has no network client, no analytics and no AI. Student records live in a file on the school's PC. The only copies are the ones the school makes.

What the desktop app stores

Everything sits in one folder on the machine where you installed it:

%APPDATA%\org.agentmark.hub\agent-mark-hub\
hub.db SQLite database (roster, scores, flags, comments, reports, audit)
backups\ encrypted backup blobs and their manifests

The database holds student names, class codes, scores, teacher comments, approvals, report payloads, and the school's signing key. It is protected by your Windows account, not by a separate password — which is why the pilot runs on a single staffroom PC.

What leaves the device

Nothing. The application contains no HTTP client for student data, no relay account, no licence check and no crash reporting. You can unplug the network cable and every feature still works.

  • The installer may fetch Microsoft's WebView2 runtime if the PC has never had Edge. That request goes to Microsoft and contains no school data.
  • Backup files are written where you choose; if you copy one to a USB stick, that is your action, not the app's.
  • This website is static. It sets no cookies, loads no fonts or scripts from third parties, and includes no analytics.

No AI, by design

There is no model, no inference, no training set, no prompt and no API key. Comments come from a reviewed bank of sentences that a teacher chooses and edits. Averages are weighted arithmetic; grade bands are fixed thresholds; ranking is competition rank. Given the same scores, the same card comes out in ten years' time.

Backups are sealed

Backups are encrypted with XChaCha20-Poly1305 and accompanied by a manifest of counts and a database hash. A restore drill decrypts the blob, re-hashes it and compares — the drill must pass before the term can go live.

Honest limitation: the encryption key is stored in the same local database. That protects a backup file that leaks on its own; it does not protect against someone who has the whole data folder. Passphrase-wrapped and split-custody keys are on the roadmap, not in this build.

Signatures and audit

Locking a report re-hashes the exact payload and signs it with Ed25519. The signature is returned as AGM1:<report-id>:<sha256>:<signature> so it can travel with a printed card as a QR code later. Every action appends a row to an audit log where each row hashes the previous one; altering history breaks the chain.

Verify a build yourself

Two independent checks ship with the project — neither trusts the app's own UI.

1. Check the download

Get-FileHash .\Agent-Mark-Hub-0.1.0-x64-setup.exe -Algorithm SHA256

Compare with the value on the download page.

2. Check a database

The offline checker re-computes the audit chain, verifies the Ed25519 signature of every locked report, and greps backup blobs for plaintext student data:

python tools\verify_db.py "%APPDATA%\org.agentmark.hub\agent-mark-hub\hub.db"

Expected output ends with RESULT: PASS. It opens the database read-only.

The pilot gate

Real student data is not allowed yet. This is a pilot build for evaluation with synthetic data. An external security review must close the findings below, and the pilot charter and parent notice must be signed, before a school enters a real name.

Open items, stated plainly:

  • No lock screen. Roles (teacher, head) are asserted by whoever uses the app. That is acceptable for one trusted staffroom PC; it is not acceptable for multi-staff use.
  • The signing key is not passphrase-protected. It is generated locally and never leaves the machine, but it is not yet wrapped or split between custodians.
  • Backups are a summary payload, not yet a full encrypted table dump with a restore-into-fresh-database routine.
  • No code signing certificate on the installer, so Windows SmartScreen warns on first run.
  • No installer for managed deployment (MSI/GPO) yet.

The threat model, the test strategy and the backup/restore runbook are maintained in the project repository alongside the source.

Mobile app

The mobile app is a separate, deliberately limited companion. It stores its demo data in the phone's browser storage. It has no account, no sync and no way to reach the school PC. Clearing the site data or removing the home-screen icon removes its data.

Who is responsible

The school remains the data controller. Agent Mark is software installed on the school's own equipment; it does not operate a service that receives student records. Questions about a specific deployment should go to the school's data protection lead.
